# Strix 报告历史与精准进度设计

## 目标

让授权测试任务有真实可读的进度、可恢复的报告历史和下载入口；关闭网页公网入口时，后台 Runner、测试靶场和报告数据仍继续工作。

## 范围

第一阶段实现以下功能：

1. Runner 持久化每次扫描的状态、阶段、进度说明和更新时间。
2. UI 显示真实阶段和心跳时间，区分“扫描中”和“模型生成建议”。
3. UI 提供历史扫描列表，显示目标、开始时间、终态和问题数。
4. 报告支持下载 Markdown 和 JSON；下载前仍要求 UI 会话认证。
5. 数据保留 90 天，并在磁盘接近阈值时给出提示；不自动删除正在运行的扫描。
6. Runner 继续只接受精确白名单目标，保留当前授权校验和单任务并发限制。
7. 解绑公网网页域名，保留 UI 服务、Runner、持久卷和内部访问能力。

第二阶段再考虑队列、多渠道通知、白名单管理页和 SARIF 下载，不在本次改动中扩大安全边界。

## 设计

### Runner API

- `GET /v1/scans` 返回最近的扫描摘要，默认最多 100 条。
- `GET /v1/scans/{id}` 返回 `status`、`phase`、`progress`、`message`、`startedAt`、`updatedAt`、`finishedAt`、`exitCode`。
- `GET /v1/scans/{id}/report` 保持现有 JSON 报告契约。
- `GET /v1/scans/{id}/report/download?format=markdown|json` 返回附件，并设置安全的固定文件名。

所有接口继续使用 Runner Bearer Token；UI 只通过服务端代理访问，浏览器不接触 Runner Token 或模型密钥。

### 进度来源

扫描启动时写入 `preparing`；子进程启动后写入 `scanning`；检测到 CLI 已结束但报告仍在生成时写入 `analyzing`；报告文件完成后写入 `reporting`，最后写入终态。每次状态变化都原子写入持久卷，`updatedAt` 用于识别停滞任务。

### 报告存储和保留

继续使用 `/data/runner-state` 和 `/data/strix_runs`。历史列表从持久化状态文件读取，报告文件按扫描 ID 关联。清理只删除超过 90 天且已结束的扫描目录及状态文件；清理失败只记录告警，不影响新扫描。

### UI

当前扫描卡片显示“第 N 阶段 / 共 4 阶段”、阶段名、说明、已用时间和最近更新时间。历史列表可打开报告抽屉，提供“下载 Markdown”和“下载 JSON”。任务运行期间不显示完成百分比，避免把阶段编号误解成真实百分比。

### 公网关闭

解绑 `strix-security-wjy.zeabur.app` 的公网域名，不删除 `strix-ui-next` 服务。Runner 的私网地址、测试靶场和 `strix-data` 数据卷保持不变；需要查看 UI 时再临时绑定域名或使用内网入口。

## 错误处理

- Runner 重启后，未结束扫描标为 `failed`，并保留已有日志和报告文件。
- 报告不存在或仍在生成时，下载接口返回明确的 404/409，不生成空文件。
- 历史文件损坏时跳过该条记录并显示“记录不可读”，不阻塞其他报告。
- 下载内容不包含 Runner Token、UI Token、模型密钥或原始执行日志。

## 验收标准

1. 自动化测试覆盖历史列表、阶段字段、下载响应、认证和保留清理边界。
2. 一次真实授权靶场扫描能看到阶段变化，并在完成后出现在历史列表。
3. Runner 重启后，历史状态和报告仍可读取。
4. Markdown 和 JSON 下载文件内容与报告接口一致，文件名不包含目标中的路径字符。
5. 公网域名解绑后，Runner 健康检查和后台扫描不受影响。
6. 未登录请求不能读取历史或下载报告。
