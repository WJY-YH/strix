# Strix ZIP 上传扫描设计

## 目标

让已登录 Strix UI 的用户上传本地 ZIP 代码，使用现有 Runner 和 Strix 引擎扫描，并继续保留进度、报告和 Markdown 下载能力。

## 范围

- 支持单个 `.zip` 文件，默认最大压缩包大小 100 MB。
- ZIP 只在扫描期间保留；扫描结束、失败或停止后删除源码和压缩包。
- 报告仍按现有 7 天策略保留。
- 解压目录必须位于 Runner 数据目录内；拒绝绝对路径、`..` 穿越、符号链接、ZIP 炸弹和空压缩包。
- UI 使用现有访问密码会话；上传接口和扫描接口都继续使用服务端认证。
- 不在本次范围内实现网站登录态继承。该功能需要独立浏览器会话桥接，且 2FA 必须由用户手动完成。

## 数据流

1. 浏览器选择 ZIP，UI 服务把文件流转发到 Runner `/v1/uploads`。
2. Runner 校验大小和 ZIP 条目安全性，将文件写入临时上传目录并返回一次性 `uploadId`。
3. UI 以 `type=local_code`、`target=uploadId` 创建扫描。
4. Runner 将 ZIP 解压到该扫描的隔离源码目录，启动 `strix --target <目录>`。
5. 扫描结束或进入终态后删除源码目录和 ZIP；报告目录不受影响。

## 错误与限制

- 文件不是 ZIP、超过大小、包含路径穿越/符号链接/过多条目/过大解压体积时返回明确中文错误。
- 同时只允许一个扫描，沿用现有 `busy` 响应。
- 上传中断不得留下可复用文件；清理任务删除过期上传目录。

## 验收标准

- UI 能选择 ZIP 并显示文件名、大小和上传状态。
- 上传成功后可创建本地代码扫描，进度、历史和 Markdown 报告与仓库扫描一致。
- 安全拒绝测试覆盖路径穿越、符号链接、超限和无效 ZIP。
- 现有网站/仓库扫描和认证回归测试全部通过。
